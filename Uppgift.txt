Generell projektbeskrivning: 
Skapa ett Monitoreringssystem:
Monitoreringssystemet ska kunna visa cpu användning, ram-minnes användning och disk användning.

Monitoreringssystemet ska reagera på konfigurerade larm; när cpu -, ram - eller diskanvändning överskrider konfigurerad nivå.

 

Skapa ett larm-konfigurationssystem:
larm-konfigurationssystemet ska kunna konfigurera alarm.

larm-konfigurationssystemet ska kunna skicka alarm till Monitoreringssystemet.

 

Skapa ett Loggsystem:
Loggsystemet ska logga användarval, aktiverade funktioner, information och felmeddelanden.

Loggsystemet ska spara logg till persistent data.

 

Frivilligt tillägg:
Det är tillåtet att skapa system utanför beskrivning i syfte att uppnå Krav för Godkänd Nivå (G).

 

Krav för Godkänd Nivå (G):
Krav: Larm-konfigurationssystem
Larm-konfigurationssystem start:

presentera användaren med en meny med val:

Lägg till alarm
Ta bort alarm
Lista alla konfigurerade alarm
Skicka konfigurerade alarm till Monitoreringssystem
Avsluta Larm-konfigurationssystem program
 

Larm-konfigurationssystem Lägg till alarm:

Användaren kan skapa ett alarm efter kategori och nivå, som läggs till i sekvens av alarm.

Det ska finnas kategorier för cpu alarm, ram-minne alarm och disk alarm.
Nivå ska vara på en skala från 0 till 100 (decimaltal) procent
 

Larm-konfigurationssystem Ta bort alarm: 

Användaren kan ta bort ett alarm från sekvens av alarm, utifrån index av alarm i sekvens

 

Larm-konfigurationssystem Lista alla konfigurerade alarm: 

Användaren kan presenteras med sekvens av alarm, sorterad utifrån kategori och nivå.

 

Larm-konfigurationssystem Skicka konfigurerade alarm till Monitoreringssystem:

Användaren kan spara sekvens av alarm till persistent data som kan delas med Monitoreringssystem.

Denna persistent data ska endast uppdateras vid utförande av funktionen.
 

Larm-konfigurationssystem Avsluta Larm-konfigurationssystem program:

Användaren kan avsluta programmet

 

Larm-konfigurationssystem: 

Innan programmet avslutas ska sekvens av alarm sparas till persistent data

När programmet startar ska det ladda sekvens av alarm sparat i persistent data

Innan programmet startar ska användaren kunna beskriva en sekvens av användarval som utförs när programmet startar.

Det är ok att leda användaren mot att utföra beskriven funktionalitet i flera steg än ett.

 

Krav: Monitoreringssystem
Monitoreringssystem start:

presentera användaren med en meny med val:

Ladda alarm
Starta monitorsession
Avsluta Monitoreringssystem program
 

Monitoreringssystem Ladda alarm:

Användaren kan ladda sekvens av alarm från persistent data som kan delas från  Larm-konfigurationssystem.

 

Monitoreringssystemet Starta monitorsession:

Användaren kan bestämma längden på en loop.

Längden kan vara i form av tid eller iterationer
Längden kan vara från 1 till oändligt
Loopen kan avbrytas (KeyboardInterrupt), utan att avsluta programmet
När loopen är startad ska användaren presenteras med information om:

cpu användning
ram-minne användning
disk användning (root directory)
Alla alarm där nivå överskrids nuvarande cpu -, ram-minne och disk användning
 

Monitoreringssystem Avsluta Monitoreringssystem program:

Användaren kan avsluta programmet

 

Monitoreringssystem:

Innan programmet startar ska användaren kunna beskriva en sekvens av användarval som utförs när programmet startar.

När programmet startar ska det Ladda alarm

Det är ok att leda användaren mot att utföra beskriven funktionalitet i flera steg än ett.

 

Krav: Loggsystem
 

Loggsystem start:

Loggsystem ska starta när Larm-konfigurationssystem eller Monitoreringssystem startar.

Loggsystem ska skapas en unik loggfil.

 

Loggsystem logg:

Loggfilen ska under det associerade programmets gång fyllas med information:

Vilka användarval som utförts
Information som presenteras för användare
Persistent data som laddats in
Persistent data som sparats
Aktiverade systemfunktioner
Fel och felmeddelanden
(En annan användare ska kunna återskapa exakt samma användarsession som tidigare, genom att följa information i loggfil)

Varje information i loggfilen ska vara associerat med datum-tid. (tips: se datetime modulen, för att uppnå unik loggfil namn och associera logg data med datum-tid)

 

Loggsystem Implementation:

Loggsystem ska endas implementeras i annan utvecklares utvecklade kod i form av funktion.

 

Krav: implementationstekniker
Vid utveckling av projektet ska tekniker användas:

Klasser
Funktioner
Variabler
Koncept innom funktionella paradigm (ex. Recursion, pure functions eller first-class functions)
Errorhantering
git
Viss grad av Best Practice
 

Krav för Väl Godkänd Nivå (VG):
Krav: implementationstekniker
Vid utveckling av projektet ska ytterligare tekniker användas:

Hög grad själv dokumenterande kod
Hög grad intuitiv dokumenterande logg från Loggsystem
Hög grad intuitivt användargränssnitt
Hög grad av Best Practice
Implementera unit tester för implementerade funktioner.
 

Best practice:
Om du spenderar 3+ rader kod åt att lösa ett problem borde de vara tillhörande en funktion.

Om du spenderar 3+ funktioner åt ett problem borde de vara tillhörande en klass.

Självdokumenterande kod.

Använd Git branches för att isolera utveckling av specifika funktioner, innan utvecklade funktioner slås ihop i main branch.

Använd Git för att göra commits ofta. (ca. ~ varje ny funktion, innan varje programmtestkörning, varje paus, varje arbetsdagsslut)

 

Grupprojektskrav:
Även om helheten av projektet är ett gruppprojekt kommer ni bedömas individuellt. (På en individuell nivå ska man ha uppfyllt Krav: implementationstekniker)

Använd Git för att samarbeta i projektet.

Gruppmedlemmar måste delta i grupparbete tillsammans på gemensam plats minst 1 gång i veckan.

Gruppmedlemmar måste vara tillgängliga för kommunikation, och förmedla vilka tider och verktyg som kan användas för kommunikation. 

Hänvisa tydligt i README fil om vem som är delegerad att ansvara och utveckla vilka krav, klasser och funktioner.
